the leap — the “ohhh”

An agent is just a thing with state & logic

Entity→an agent, a task, a shared blackboard — just an id
Component→all state — Messages, ModelRef, PendingToolCalls, errors, interrupts
System→callLLM · executeTools · supervisor · healer
add / remove a component→what triggers systems — replaces edges & routers
World→entities + systems + resources + scheduler + snapshot
components hold only JSON; behavior — models, tools, DB — registers as a named resource: ModelRef("model:main"). that one rule is why a snapshot is plain JSON any process can resume.
the twist — vs games AND vs LangGraph

Kill the tick loop.
Kill the edges.

A (system, entity) pair fires only on a foreign write to a component it watches. Its own writes never re-trigger it. Control flow emerges; the run ends at quiescence.

feature, in motion

Errors are components.
Healing is a system.

A throwing system isn't a crashed run.

The engine discards its writes → appends a SystemError chip.

A healer watches ⟨SystemError⟩, retries, and it auto-clears.

the part that actually matters

What a graph framework can't copy

Agents are data, not structure. N agents = N entities on one set of systems. Spawn a teammate mid-run — no graph to recompile.
Query the whole world. One query powers a budget guard, a router, or a trace logger across every agent at once.
Failure is queryable state. A supervisor heals a worker by reading its SystemError — no exception unwinds your run.
Survives process death. Pause is a JSON file you can cat; resume in a brand-new process.
Three agents in one step. A deterministic parallel super-step; reducers merge the fan-in.
Every win here is a run-time property.
The trade-offs are read-time legibility & ecosystem age — and those are tooling-fixable.

You can't retrofit “three agents thinking in one step” onto a compiled graph.
be honest — it isn't always the answer

Graph, or world?

Reach for a graph
LangGraph, today
  • You want to read the flow cold — a drawn topology beats implicit firing
  • A simple, linear pipeline — few steps, fixed order
  • You need a mature ecosystem & hosted platform — Studio, managed persistence
  • Durable Postgres / Redis checkpointers now (LangECS's are roadmap)
  • Pause mid-node at an arbitrary line · polished token-streaming UX
Reach for a world
LangECS
  • Many agents — spawned, supervised & healed at runtime
  • Failure as state you can query, retry, and heal
  • Kill & resume across processes, by construction
  • Parallel agents in one deterministic step
  • Step-level tests + a flight recorder, zero network
