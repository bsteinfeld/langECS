# LangECS Implementation Spec

*Engineering contract for `@langecs/core` (and outline specs for the satellite packages).
Derives from `DESIGN.md`; where this document is more precise, this document wins.
Requirements are numbered (R1, R2, …) so reviews can cite them.*

---

## 0. Constraints

- **R1** `@langecs/core` has **zero runtime dependencies** and is **isomorphic**: no `node:*` imports, no Node-only globals. (`performance.now()` and `console` are allowed; guard `performance` with a fallback to `Date.now()`.)
- **R2** ESM-only, TypeScript strict (base tsconfig already in repo). All public API fully typed — no `any` leaking into public signatures.
- **R3** Everything stored in components must be structured-clone/JSON-serializable. The engine never puts non-serializable values into component storage.

## 1. Module layout (suggested, not mandated — public exports ARE mandated)

```
packages/core/src/
  index.ts        # public surface re-exports
  component.ts    # defineComponent, defineTag, global registry, Not()
  system.ts       # defineSystem
  agent.ts        # defineAgent
  world.ts        # createWorld, World, EntityHandle
  scheduler.ts    # step loop, matching, dirty-tracking, barrier
  snapshot.ts     # snapshot/load
  persistence.ts  # PersistenceAdapter, MemoryAdapter
  events.ts       # RunEvent types, Run object (promise + async-iterable)
  trace.ts        # flight recorder, formatTrace
  builtins.ts     # SystemError, AwaitingHuman, HumanResponse, Cancelled
  cancel.ts       # throwIfAborted, abortReason, delay, anySignal (R49)
  model.ts        # Msg, Model, ToolSpec, scriptedModel (no engine coupling)
  errors.ts       # WriteConflictError, WorldRunningError, UnknownComponentError, ...
```

## 2. Components

- **R4** `defineComponent<T>(opts: { name: string; reducer?: (current: T, incoming: T) => T; transient?: boolean; serialize?: (v: T) => unknown; deserialize?: (raw: unknown) => T })` returns `ComponentType<T>`.
- **R5** `ComponentType<T>` is **callable**: `Messages([...])` returns a `ComponentInit<T>` usable in `world.spawn(...)` / `defineAgent.components` / `world.send(...)`.
- **R6** `defineTag(name: string)` returns `TagType` (a `ComponentType<true>` callable with zero args).
- **R7** Component names are globally unique. A module-level registry maps `name → definition`; defining a duplicate name **throws immediately**. Registry is needed so snapshots can be rehydrated by name (reducers/serializers re-attach).
- **R8** `Not(C)` produces a negative query term. Query terms: `ComponentType<any> | NotTerm`.

### Built-in components (defined by core, in the registry like any other)

- **R9** `SystemError`: `ErrorRecord[]` with **append reducer**. `ErrorRecord = { system: string; step: number; error: { name: string; message: string; stack?: string } }`.
- **R10** `AwaitingHuman`: `InterruptRecord[]` with **append reducer**. `InterruptRecord = { id: string; kind: string; payload?: unknown }` (`id` generated by the engine helper or supplied).
- **R11** `HumanResponse`: `{ value: unknown }`, no reducer (replace).
- *(added, R50)* `Cancelled`: `{ step: number; reason?: string }`, no reducer (replace). Stamped on every entity by `world.cancel()`; the conventional guard term is `Not(Cancelled)`.

## 3. World, entities, mutations

- **R12** `createWorld(opts?: { id?: string; persistence?: PersistenceAdapter; recursionLimit?: number; trace?: boolean | { keep?: number }; systemTimeoutMs?: number; recipeVersion?: number; saveEvery?: 'barrier' | 'quiescence' | number; fence?: boolean })` → `World`. Defaults: `id: 'world'`, `recursionLimit: 50`, trace on keeping last 1000 steps, **no** system timeout (R52), `recipeVersion: 0` (R54), `saveEvery: 'barrier'` (R58), fencing off (R57).
- **R13** Entity ids are numbers, starting at 1, monotonically increasing, never reused within a world.
- **R14** `world.spawn(...items: (ComponentInit | AgentDef)[])` → `EntityHandle`. Spawning an `AgentDef` applies its component bundle + auto-tag (see R34) and **idempotently registers its systems** on the world.
- **R15** `EntityHandle` / in-system `EntityView` share: `id`, `has(C)`, `get(C)` (typed; see §9), `components(): string[]`. Mutators: `add(C, value)` (merge via reducer if the component has one, else set), `set(C, value)` (replace, bypasses reducer), `remove(C)`, `despawn()`. Tags: `add(Tag)` with no value.
- **R16** **External mutations** (via `EntityHandle` while the scheduler is idle) apply immediately and are recorded as external dirt for the next run. Mutating externally **while a run is in flight throws** `WorldRunningError`. *(amended)* `world.cancel()` (R50) is the single exception — see there for why it is still barrier-safe.
- **R17** **In-system mutations** (via the `EntityView` passed to `run`, or `ctx.write/remove/despawn/spawn`) are **buffered per (system, entity) pair** and applied only at the step barrier. During a step, all reads (`get/has`, `ctx.world.query`) see the **step-start state** — systems never observe each other's same-step writes.
  *(amended)* **Read-isolation carve-out:** `get()` (on any view or handle) returns committed values **by reference** and they must be treated as **immutable**. In-place mutation of a returned value is **undefined behavior** — it is not detected, generates no dirt and no conflict, and may be observed by other pairs mid-step. The isolation guarantee above applies only to mutations recorded through the API (`add`/`set`/`remove`/`ctx.write`).
- **R18** `world.register(name: string, resource: unknown)` / `ctx.resource<T>(name): T` (throws a clear error naming the missing resource). Resources are never snapshotted.
  *(amended)* **Typed resource references:** `defineResource<T>(name: string): ResourceRef<T>` creates a typed name — no global registry, no uniqueness rule, runtime shape `{ resourceName }` with `T` phantom. `world.register<T>(ref, value: T)` and `ctx.resource<T>(ref): T` (also on `GuardCtx`) are overloads over the **same string-keyed slot**: a ref and its `resourceName` string are interchangeable (register by one, read by the other), and `MissingResourceError` is unchanged — it names the resource.
- **R19** `world.use(systemDef | agentDef)` registers a global system, or (for an `AgentDef`) registers its scoped systems **without spawning** — required before `world.load()` of a snapshot containing that agent's entities.
- **R20** `world.query(...terms)` (outside a run) → `EntityHandle[]` over committed state, ordered by entity id. *(amended)* Zero-term (`world.query()` → all entities) and negative-only (`world.query(Not(C))` → the complement) queries are supported debugging API; the positive-term requirement applies only to system queries (R21).

## 4. Systems

- **R21**
  ```ts
  defineSystem({
    name: string,                       // unique per registration scope
    query: QueryTerm[],                 // at least one positive term
    when?: (e, ctx: GuardCtx) => boolean, // SYNC guard, read-only view (amended: restricted ctx)
    run: (e, ctx) => void | Promise<void>,
    timeoutMs?: number,                 // wall-clock budget for one execution (R52)
  })
  ```
  *(amended)* `when` guards receive a **restricted `GuardCtx = { step, world, resource }`** — at both the type level and at runtime. Guards can never buffer writes, spawn, despawn, invalidate, or `emit`; they are pure reads over the step-start state.
- **R22** `ctx` (SystemCtx): `{ step: number; world: ReadView (query/entity over step-start state); spawn(...inits): EntityHandle-like (see R29); despawn(target); write(target, C, value, op?: 'add' | 'set'); remove(target, C); emit(data: unknown): void; resource<T>(name): T; invalidate(target, system?: string): void }`. `target` accepts an id, `EntityHandle`, or `EntityView`.
- **R23** `ctx.emit(data)` pushes a `custom` event to the live run event stream immediately (mid-step). Emitted data is observation only — never stored, never snapshotted.
- **R24** `ctx.invalidate(target, system?)` manually marks (system, entity) — or all systems for the entity — dirty for the next step. (Escape hatch; stdlib retry uses it.) *(amended)* An unknown system name rejects the run during barrier staging (boundary intact, like R30); an invalidate whose target entity does not exist at the barrier (never spawned, or despawned this step) is dropped and recorded in the trace's `droppedWrites` — phantom dirt never reaches `pendingPairs` (R35).

## 5. Step algorithm

- **R25** `world.run(opts?: { limit?: number })` → `Run`. Only one run at a time (second call throws). `world.send(target, ...inits)` = external adds + `run()`.

  ```
  run loop (step = world.step + 1, ...):   (amended: limit before guards; two-phase barrier)
    1. CANDIDATES = all (system S, entity e) where:
         a. S.query matches e in committed state, AND
         b. pair is dirty (see R26)
    2. if CANDIDATES empty → quiescent. break.
    3. if steps executed this run ≥ limit → status 'limit'. break.
       (amended: the limit is checked BEFORE guard evaluation — at a limit break
        no guard code runs and no dirt is consumed, so a later run resumes and
        replays every pending pair, including guard vetoes and guard throws.)
    4. ELIGIBLE = candidates with S.when(e, guardCtx) !== false
       (when-veto recorded in trace; the veto's dirt is consumed at the barrier
        commit — or at this boundary when ALL candidates veto and the run
        quiesces with a vetoed-only trace entry).
       if ELIGIBLE empty → quiescent. break.
    5. emit step:start. Execute ALL eligible pairs concurrently (Promise.all);
       each pair records mutation ops (in call order) into its own buffer.
       A pair that throws: buffer discarded, SystemError record appended (R31).
       (amended: each pair races its own `timeoutMs` (R52). When the deadline
        wins, the barrier STOPS WAITING for that pair — it is abandoned, not
        awaited — its buffer is discarded, further ops from it are refused, its
        `ctx.signal` is aborted, and a SystemTimeoutError is recorded like any
        throw. A pair with no timeout is awaited to settlement as before.)
    6. BARRIER — two-phase (amended):
       STAGE (validates/evaluates everything that can throw, against a staging
       overlay, with committed state untouched):
         - conflict prescan (R30) and invalidate validation (R24);
         - every reducer evaluation ('add' on reducer component:
           value = reducer(current, incoming); 'add' on plain component = 'set');
         - spawn-time agent-system registration keys (duplicates reject here);
         - despawn resolution: writes targeting a despawned entity are dropped
           and noted in the trace.
       Any staging throw REJECTS the run with component state, dirt, the step
       counter, and the trace ALL at the step-start boundary.
       COMMIT (unconditional; runs no user code, cannot throw):
         - consume dirt for executed and vetoed pairs (R26 amended);
         - apply staged values sorted by (system registration index, entity id),
           ops in call order within a pair;
         - spawns materialize (ids were allocated eagerly at ctx.spawn call, R29);
         - despawns apply AFTER all writes;
         - engine SystemError append (R31) and auto-clear: for every pair (S, e)
           that completed successfully, remove S's records from e's SystemError
           if present (R32).
    7. Compute dirty marks for next step (R26). Record step trace. Emit step:applied.
    8. world.step++. If persistence adapter configured: await adapter.save(world.snapshot()).
    9. goto 1.
  ```

- **R26** **Dirty rules.** Pair (S, e) is dirty for step N+1 iff any of:
  1. a component in S's positive query terms changed on e during step N — added, removed, set, or reducer-merged — **by a writer other than (S, e) itself** (engine writes like SystemError count as foreign);
  2. S's query **newly matches** e at the end of step N (did not match at end of step N−1) — including matches created by removal of a `Not()` term component, by spawn, or by system registration;
  3. external mutations touched e's queried components (or created a new match) while idle (R16);
  4. `ctx.invalidate` targeted it.
  Any `set/add` counts as a change **even if the value is deep-equal** (no equality checking). A when-veto consumes dirt: the pair will not re-fire until new dirt arrives. Removal of a positive-term component simply unmatches (no fire).
  *(amended)* **Dirt is consumed only at the barrier commit** — for executed pairs and for when-vetoes alike (a veto in a fully-vetoed, zero-step iteration consumes at that quiescent boundary). If the barrier rejects during staging (R30 conflict, unknown invalidate target, throwing reducer, duplicate agent-system key), all dirt is left intact: the work stays re-runnable and every snapshot remains boundary-consistent (R35).
- **R27** Self-write exclusion is per **pair**: if (S, e1) writes to e2's queried components, that is foreign dirt for (S, e2).
- **R28** Quiescence result statuses, in precedence order: *(amended)* `'cancelled'` (≥1 entity has `Cancelled`, or `world.cancel()` was called during this run) > `'error'` (≥1 entity has non-empty SystemError) > `'pending'` (≥1 entity has AwaitingHuman records) > `'done'`. A run that scheduled zero steps returns `'idle'`. Hitting the limit → `'limit'`. *(amended)* `'cancelled'` must outrank `'error'` and `'limit'`: aborting an in-flight call makes it throw, so if failure won the tie every cancellation would be indistinguishable from a crash. Like `'error'` and `'pending'`, it is read from committed state, so it needs no engine flag to reset — removing `Cancelled` un-cancels the world. `RunResult = { status; steps: number; pending: { entity: number; interrupts: InterruptRecord[] }[]; errors: { entity: number; records: ErrorRecord[] }[] }`. *(amended)* `RunResult.pending`/`errors` and `world.pending()` return **detached copies** — mutating them never touches committed component state.
- **R29** `ctx.spawn(...inits)` allocates the entity id **eagerly** (synchronously, from the world counter) and returns a handle whose components materialize at the barrier. *Documented caveat:* when multiple concurrently-executing pairs spawn in the same step, id assignment order follows await-interleaving; ids are opaque — semantics are unaffected, but byte-identical replay of such steps is not guaranteed. The trace records every spawn with its creator pair.
- **R30** **Write conflicts.** If two or more **different pairs** write (add/set) the same plain (reducer-less) component on the same entity in one step → throw `WriteConflictError` from `run()`, naming the component, entity id, step, and both systems. Reducer components merge all writers' adds in deterministic barrier order; a `set` on a reducer component replaces the accumulated value at its position in the order (allowed, deterministic, but documented as sharp). *(amended)* The conflict is detected in the barrier's **staging** phase: the run rejects with component state, dirt, the step counter, and the trace all at the step-start boundary — re-running the world **reproduces the conflict** rather than silently losing the pending work.
- **R31** **Errors.** A throwing `run` (sync or rejected promise) → that pair's buffer is discarded entirely; the engine appends an `ErrorRecord` to the entity's `SystemError` (this is an engine write at the barrier, exempt from R30, attributed as foreign dirt). Other pairs in the step commit normally. A throwing `when` guard is treated the same as a throwing `run`. *(amended)* One exception: a pair that failed **because the world was cancelled** (R50) discards its buffer but gets **no** `ErrorRecord` — recording one would report a deliberate stop as a crash and would invite a retry system to re-arm the very work the operator just cancelled. A **timeout** (R52) is not an exception and does record, precisely so it can be healed.
- **R32** When pair (S, e) later **succeeds**, the engine removes S's records from e's `SystemError` at that barrier (counts as a foreign change for dirty purposes).

## 6. Interrupts (human-in-the-loop)

- **R33** `world.pending()` → `{ entity, interrupts }[]` from committed state. `world.resume(target, value: unknown)` (external, idle only): removes `AwaitingHuman` entirely, sets `HumanResponse({ value })`, and runs to quiescence. Convention: systems consume (`remove`) `HumanResponse` when they act on it. *(stdlib builds approval flows on these; core knows nothing about tools.)*

## 7. Agents & scoping

- **R34** `defineAgent({ name, components: ComponentInit[], systems?: SystemDef[] })` → `AgentDef`. Spawning adds a hidden-by-convention tag component named `agent:<name>` (a real component, present in snapshots). Each declared system is registered (idempotently, key `<agentName>:<systemName>`) with its query **automatically narrowed** by the agent tag. Systems registered via `world.use(systemDef)` are global (no narrowing). Spawn-time extra inits override bundle inits for the same component. *(amended)* Spawn materialization (external and `ctx.spawn`) **deep-copies init values** via structured clone: entities spawned from the same `AgentDef` (or a reused `ComponentInit`) share no object identity, and in-place mutation of a spawned value can never corrupt the template.

## 8. Snapshots & persistence

- **R35** `world.snapshot()` (sync) →
  ```ts
  { version: 1,                    // ENVELOPE FORMAT version — engine-owned
    recipeVersion?: number,        // APPLICATION VOCABULARY version — yours (R54)
    worldId, step, nextEntityId,
    entities: [{ id, components: Record<name, unknown> }],   // transient components excluded;
                                                             // serialize() hooks applied
    pendingPairs: { entity: number; system: string; reason: string }[] }  // dirt at this boundary
  ```
  JSON-stringifiable always (R3 + serialize hooks). *(amended)* `version` and `recipeVersion` are **different things and must stay separate fields**: the first versions the shape of this envelope and changes when the engine changes; the second versions the caller's own component/system names and changes when the application does. Collapsing them would make every engine release look like a schema migration, and every schema migration look like a format break. `recipeVersion` is omitted entirely at 0, so worlds that never opt in keep writing byte-identical snapshots.
- **R36** `world.load(snapshot, opts?: { strict?: boolean; expectedStep?: number }): LoadReport`: requires all component names resolvable in the registry and all `pendingPairs` systems registered (via `world.use`) — otherwise throws listing what's missing. *(amended)* Registered migrations (R54) run **before** any name is resolved, which is what lets a migration rename a component the running build no longer defines. Returns a `LoadReport = { migrated: {from,to}[]; preserved: {entity,component}[]; droppedPairs: PendingPair[] }`, empty everywhere on a clean strict load. Restores entities (deserialize hooks), step counter, id counter, and pending dirt, so a resumed world continues **identically** from the boundary. *(amended)* `load()` replaces the previous timeline wholesale: pre-existing entities are discarded and the flight-recorder buffer (R42) is cleared, so the trace never mixes steps from two histories.
- **R37** `PersistenceAdapter = { save(s: Snapshot): void | Promise<void>; load(worldId: string): Promise<Snapshot | null> | Snapshot | null; history?(worldId): ...{ step, savedAt }[]; loadStep?(worldId, step): ...; fence?(worldId, step): boolean | Promise<boolean> }`. Engine awaits `save` at the cadence set by `saveEvery` (R58) — every barrier by default — and once at run end (quiescent boundary). *(amended)* A boundary is never written twice: the engine tracks a revision of committed state and skips a save when nothing changed since the last one, so the final step is no longer persisted at its barrier **and** again at run end.
- **R38** `MemoryAdapter` ships in core: full history per worldId, `history()`/`loadStep()` implemented → time travel = `createWorld` + `use(...)` + `load(await adapter.loadStep(id, n))`.

## 9. Type inference (DX acceptance criteria — these MUST compile/infer as stated)

```ts
const Messages = defineComponent<Msg[]>({ name: 'messages', reducer: (a, b) => [...a, ...b] })
const ModelRef = defineComponent<string>({ name: 'modelRef' })
const Busy = defineTag('busy')

const callLLM = defineSystem({
  name: 'callLLM',
  query: [Messages, ModelRef, Not(Busy)],
  when: (e) => e.get(Messages).length > 0,          // e.get(Messages): Msg[]  (non-nullable)
  run: async (e, ctx) => {
    const m: string = e.get(ModelRef)               // string (non-nullable: positive term)
    e.add(Messages, [{ role: 'assistant', content: 'hi' }])  // value type-checked as Msg[]
    const other = e.get(Busy)                       // true | undefined (not a positive term)
  },
})
```

- **R39** `e.get(C)` returns `T` (non-optional) for positive query terms, `T | undefined` otherwise. `add/set` values are typed. No manual generics at call sites. Use tuple inference over the `query` array. Verify with `expectTypeOf` tests in vitest.

## 10. Events & flight recorder

- **R40** `Run` implements `PromiseLike<RunResult>` **and** `AsyncIterable<RunEvent>`. Iterators replay buffered events from run start, then go live (no missed events regardless of when iteration starts). *(amended)* When the run **rejects** (e.g. `WriteConflictError`, a throwing reducer), async iterators drain all buffered events and then **throw the rejection reason**; promise consumers observe the same rejection. A rejected run emits no `run:end`.
- **R41** `RunEvent` union (all carry `step` where meaningful):
  `run:start {runId}` · `step:start {step, scheduled: {system, entity}[]}` · `system:start {system, entity}` · `system:end {system, entity, ms}` · `system:error {system, entity, error}` · `custom {system, entity, data}` (from `ctx.emit`) · `step:applied {step, changes: ChangeRecord[], spawned: number[], despawned: number[]}` · `run:end {status, steps}`.
  `ChangeRecord = { entity, component, kind: 'set' | 'merge' | 'remove', value?: unknown }`.
  *(amended)* Every `system:error` is preceded by a `system:start` for the same pair (a throwing `when` guard emits both, back to back). `ChangeRecord.value` is a **detached copy** (structured clone), never a live reference to committed storage. Note: `step:start.scheduled` is the **post-guard** eligible pairs; the flight recorder's `StepTrace.scheduled` (R42) is the **pre-guard** matched+dirty candidate list, with guard vetoes listed separately in `vetoed` — the two lists differ for any step with a veto.
- **R42** Flight recorder (when trace enabled): per-step `StepTrace = { step, scheduled: {system, entity}[], vetoed: {system, entity}[], runs: {system, entity, ms, error?, writes: ChangeRecord[]}[], applied: ChangeRecord[], spawned: number[], despawned: number[], droppedWrites?: ..., durationMs }`. `world.getTrace()` returns the ring buffer; `formatTrace(steps)` renders a compact human-readable text block (the "pretty console printer"). *(amended)* Trace `ChangeRecord` values are detached copies (same rule as R41): later mutation of committed state can never rewrite recorded history, and mutating a trace entry never touches committed state.

## 11. Model contracts (types only — engine does not use them)

- **R43**
  ```ts
  type Msg = { role: 'system' | 'user' | 'assistant' | 'tool'; content: string;
               toolCalls?: { id: string; name: string; args: unknown }[];
               toolCallId?: string; name?: string;
               thinking?: string;                       // reasoning text, output-only, never sent back
               meta?: Record<string, unknown> }
  type ToolSpec = { name: string; description?: string; parameters?: Record<string, unknown> /* JSON Schema */ }
  interface ModelRequest { messages: Msg[]; system?: string; tools?: ToolSpec[];
                           temperature?: number; maxTokens?: number;
                           // sampling controls: forwarded by adapters only when set
                           topP?: number; topK?: number;
                           frequencyPenalty?: number; presencePenalty?: number;
                           seed?: number; stopSequences?: string[];
                           signal?: AbortSignal }       // cooperative cancellation (R49)
  interface ModelResult { message: Msg; usage?: { inputTokens?: number; outputTokens?: number };
                          finishReason?: string; raw?: unknown }
  interface Model { generate(req: ModelRequest): Promise<ModelResult>;
                    stream?(req: ModelRequest, onChunk: (d: { text?: string }) => void): Promise<ModelResult> }
  ```
- **R44** `scriptedModel(turns, opts?)` → deterministic `Model` for tests: returns turns in order (supports `stream` by chunking content); throws if called more times than scripted. Exported from core.
  `turns: (Msg | ((req: ModelRequest) => Msg | Promise<Msg>))[]` — a turn function may return a promise, so a test can script a *slow* or never-settling call (the deterministic way to exercise R49 cancellation and R52 timeouts with zero network). `opts?: { delayMs?: number }` delays every turn by `delayMs`, interruptibly.
  *(amended)* `scriptedModel` **honours `req.signal`** (R49): an already-aborted signal rejects without consuming a turn (so the script stays aligned for the next call), and an abort during a `delayMs` wait rejects at that moment.
- **R49** **Cooperative cancellation.** `ModelRequest.signal?: AbortSignal`. The contract for a custom `Model`: check the signal before starting work, forward it to the underlying transport (`fetch`, SDK client), and reject — rather than resolve — when it aborts. Rejecting with the signal's own `reason` is preferred; core exports `CancelledError` (and `throwIfAborted(signal)`) for implementations that have no platform reason to re-throw. Cancellation is cooperative by construction: a `Model` that ignores the signal cannot be interrupted, and the engine never pretends otherwise. Both shipped adapters forward it (`@langecs/ai-sdk` → `abortSignal`, `@langecs/langchain` → the call's `signal` option) **and** enforce the reject-never-resolve rule themselves, since a provider handed an already-aborted signal may otherwise return a normal reply.
  Core also exports the isomorphic helpers this needs: `throwIfAborted(signal)`, `abortReason(signal)`, `delay(ms, signal?)` (interruptible sleep) and `anySignal(signals)`.

| T28 | `scriptedModel` + `signal` (R44/R49): an aborted call rejects **without consuming a turn**; `delayMs` is interruptible mid-call; both adapters forward the signal and reject a pre-aborted request |
| T29 | `world.cancel` mid-run (R50): `Cancelled` stamped on every entity, guarded work never lands, status `'cancelled'`, and **no** `SystemError` written for the aborted pair |
| T30 | cancellation is state (R50): survives snapshot/load, `'cancelled'` outranks `'error'`, removing `Cancelled` re-matches the systems; idle cancel applies immediately |
| T31 | `timeoutMs` (R52): a hung system becomes a `SystemTimeoutError` record while its siblings commit normally; the world-level default applies where a system sets none; a sibling timeout never aborts a healthy pair |
| T32 | abandoned pairs (R52): a write buffered by a timed-out system **after** the barrier never commits, and produces no second error |
| T33 | `runningPairs()` (R53): reports in-flight pairs with step/elapsed/timeout, empty before the run and after it settles |
| T34 | `recipeVersion` (R54): stamped and omitted at 0; separate from the envelope `version` |
| T35 | migration renames a component **and** its `pendingPairs` system, so a paused world survives a deploy; chains apply transitively in ascending order |
| T36 | migration failure modes (R54): snapshot from newer code throws with `fromFuture`, a chain gap names the missing step, two migrations from one version reject at registration |
| T37 | `canLoad` (R56): reports missing migration / component / system names, and mutates nothing |
| T38 | `strict: false` (R55): an unknown component is preserved and round-trips through the next snapshot; an unknown `pendingPairs` system is dropped **and reported** |
| T39 | `expectedStep` (R57) throws `StaleSnapshotError` on a mismatch |
| T40 | fencing (R57): two workers resume one snapshot, exactly one advances and the loser rejects with `FenceError`; `claim()` before running keeps side effects exactly-once (the save-time fence alone does not); `claim()` also rejects a worker holding a snapshot older than the adapter's latest, which the fence alone cannot catch; persisted history has no interleaved timeline; an unfenced world can still rewind and rewrite (R38) |
| T41 | `saveEvery` (R58): `'barrier'` writes once per step, `'quiescence'` once per run, `N` every N steps; no boundary is ever written twice |

## 14. Observability & introspection (devtools surface)

*Added for `@langecs/otel` and `@langecs/devtools`. Everything here is strictly
outside engine semantics: with no observers attached there is zero behavioral
difference, and a buggy observer can never change scheduling, state, or run
results.*

- **R45** `world.observe(observer: WorldObserver): () => void` attaches an observer; the
  returned detach function is idempotent **per registration** (attaching the same observer twice
  yields two independent detaches — double-calling one never removes the other). 
  `observer.onEvent?(event, { worldId, runId })` is a **passive tap** called synchronously at the
  same points the run's stream emits, for every run, regardless of whether anyone iterates the
  `Run`. `ObserverEvent = RunEvent | { type: 'run:reject'; error: SerializedError }` —
  `run:reject` fires when a run rejects at the barrier (a rejected run emits no `run:end`, R40),
  so observers can always close out a run. Exceptions thrown by `onEvent`/`onExternalChange` are
  caught and reported via `console.error` (guarded — console is not assumed, R1); they never
  affect the run. *Counter caveat:* `step:applied` is emitted **before** `world.step` increments
  (R25 step 7/8), so inside that callback `world.step`/`world.snapshot().step` still read the
  previous boundary while entities and dirt are post-step; the event's own `step` field is the
  truthful label. (Engine-persisted snapshots, R37, are taken after the increment and are
  unaffected.)
- **R46** `observer.wrapSystemRun?(info: SystemRunInfo, fn) => Promise<void>` is middleware
  around one pair's `run` execution (the async-context hook for tracing). Contract: call `fn`
  **exactly once** and propagate its settlement. `fn` rejects iff the system threw (sync throws
  surface as rejections); the engine treats any rejection of the composed wrapper as the system
  throwing (R31) — a wrapper that throws on its own is indistinguishable from a system error.
  The reverse direction is engine-enforced, not contract-hoped: the system's own failure is
  tracked out-of-band, so a wrapper that **swallows** `fn`'s rejection still yields a failed
  pair — R31's discard-entire-buffer and R32's auto-clear can never be subverted into a partial
  commit by a buggy wrapper. Wrappers compose across observers, first-registered outermost.
  `when` guards are never wrapped.
- **R47** Introspection, all read-only over committed registration state:
  `world.running: boolean` (a run is in flight, R16/R25); `world.systems(): SystemInfo[]` in
  registration order, where `SystemInfo = { key, name, agent?, query: { include: string[];
  exclude: string[] } /* effective query, auto-tag included */, hasGuard }`;
  `world.resources(): string[]` (sorted names — values are never exposed, R18);
  `listComponents(): ComponentInfo[]` (module-level, over the global registry R7), where
  `ComponentInfo = { name, tag, reducer, transient }`, sorted by name.
- **R48** `observer.onExternalChange?(change)` fires after an idle-time change commits (and after
  its dirt refresh): `{ kind: 'spawn' | 'despawn', entity }`, `{ kind: 'write' | 'remove',
  entity, component }` (one per external `add`/`set`/`remove`, including those inside
  `world.send`/`world.resume`), `{ kind: 'load' }`, `{ kind: 'systems' }` (`world.use`),
  `{ kind: 'resource', name }` (`world.register`). The payload identifies *what* changed, never
  values — consumers refetch what they render.

## 15. Cancellation, timeouts, and in-flight introspection

- **R50** **`world.cancel(reason?: string)`.** Aborts every in-flight pair's `ctx.signal` and stamps the builtin `Cancelled({ step, reason? })` component on **every** entity. `Cancelled` is ordinary component data — the third member of the queryable-run-state family with `SystemError` (failure) and `AwaitingHuman` (waiting) — so it appears in snapshots and a cancelled world reloads cancelled, and **removing it un-cancels the world** (no engine flag exists to get out of sync with the state).
  Cancellation is **cooperative and opt-in at the query level**: the standard guard is a `Not(Cancelled)` term, which every stdlib system carries (`callLLM`, `executeTools`, `toolApproval`, `retry`). A system without that term keeps matching after a cancel, by design — the engine will not decide which of a user's systems are safe to stop.
  Unlike every other external mutation (R16), `cancel` is legal **mid-run**; being able to stop a run in flight is the entire point. It still never mutates committed state from outside a barrier: mid-run the stamp is an engine write applied at the next step boundary, recorded in the trace with no runs (like a fully-vetoed iteration) and **without advancing the step counter**, so the trace and every snapshot stay boundary-consistent. Called while idle it applies immediately, like any other external write.
  The engine stops *waiting* for a pair only when that pair has a `timeoutMs` (R52). A system that ignores `ctx.signal` runs to completion and its writes commit normally.
- **R51** **`ctx.signal: AbortSignal`** — scoped to one (pair, step). It aborts when the world is cancelled (R50) **or** that system's `timeoutMs` elapses (R52), and **never** because a sibling pair timed out. Systems forward it to every awaited call (`ModelRequest.signal`, `fetch`, a DB driver, `ToolDef.execute`'s second argument) and check it in long loops with `throwIfAborted(ctx.signal)`. A fresh signal is derived per run, so a cancellation cannot leak into a later run.
- **R52** **Per-system timeouts.** `defineSystem({ timeoutMs })`, defaulted by `createWorld({ systemTimeoutMs })`; unset means no timeout. On expiry the engine: aborts that pair's `ctx.signal`, records a `SystemTimeoutError` on the entity's `SystemError` via R31's path (so `retry` can heal it and R32 auto-clears it on a later success), and **stops waiting** — the barrier commits without it.
  The abandoned `run` may still be executing. It is rendered inert rather than trusted: its buffer is discarded and **every subsequent buffered op is refused**, so a late write can never commit at a barrier the system was no longer part of, and `ctx.emit` from an abandoned pair is suppressed. Without that refusal R31's "discard the buffer entirely" would hold for throws but not for hangs. Guards are never timed (they are sync).
  This is the compatible escape from R25 step 5: before it, one system that never settled hung the barrier forever — no commit, no snapshot, no status, and `world.running` stuck `true` so external mutation threw `WorldRunningError`.
- **R53** **`world.runningPairs(): RunningPair[]`** where `RunningPair = { system, entity, step, elapsedMs, timeoutMs? }`, in scheduling order — what *is* running and for how long, completing the introspection surface of R47 (`systems()` = what could run) and `systemsMatching()` (what could run for one entity). Empty unless a run is in flight, cleared when the run settles, and safe to call mid-run including from an observer.

## 16. Snapshot evolution, fencing, and write cadence

*Everything here exists because two of the engine's headline features intersect
badly: quiescence **is** the pause (R33), so a world can sit paused for as long
as a human takes — and R36 throws on any unresolvable name. A component rename
deployed while someone's world is paused therefore made that world permanently
unloadable, with no supported answer at all.*

- **R54** **Recipe versions and migrations.** `createWorld({ recipeVersion })` declares the caller's own component/system vocabulary version (default 0), stamped into every snapshot (R35). `world.migration(from, to, fn)` registers a forward step; `world.load` applies the chain **before resolving any component name**, which is precisely what allows a migration to rename a component this build no longer defines.
  A `Migration = (snapshot: Snapshot) => Snapshot` receives a **detached deep copy**, so mutate-and-return is the expected style. Rules: the chain is walked ascending and transitively (1→2→3 for a v1 snapshot in a v3 world); two migrations sharing a `from` throw `DuplicateMigrationError`, so the upgrade path is never ambiguous (re-registering the identical edge is idempotent); a gap throws `RecipeVersionError`; and a snapshot whose `recipeVersion` is **newer** than the world's throws too, with `fromFuture: true`. That last case is deliberately not migratable — only code that knows the later schema can read it, so a rollback must fail loudly rather than misinterpret live state.
- **R55** **Non-strict load.** `world.load(snapshot, { strict: false })` resolves what it can and reports the rest instead of throwing, with a deliberate asymmetry between the two kinds of unresolvable thing:
  - An **unknown component** is **preserved as opaque data**, not dropped. It joins no query, generates no dirt and runs no reducer, but the next `snapshot()` writes it back. Dropping it would mean a rolling deploy silently destroys state that the *other* running version still owns — a far worse outcome than carrying bytes the current build cannot interpret.
  - An **unknown `pendingPairs` system** is **dropped and reported**. Unlike a component value there is nowhere to keep it: dirt names a system that has to be *scheduled*. The work it described will not run, so it is surfaced in `LoadReport.droppedPairs` rather than swallowed.
- **R56** **`world.canLoad(snapshot): LoadCheck`** — a pre-flight check with **no side effects**: nothing mutated, nothing thrown. Reports, individually: an unsupported envelope format, a `recipeVersion` from the future, a missing migration step, and the specific component and system names that would not resolve *after* migration. Built for CI and deploy gates, so an operator learns that a paused world is about to become unloadable at build time rather than from the user who paused it.
- **R57** **Resume safety.** Two independent mechanisms, because they catch the race at different moments:
  - `world.load(snapshot, { expectedStep })` throws `StaleSnapshotError` unless the snapshot sits at exactly that step. Synchronous, adapter-free, and enough to catch a resume that read a snapshot another worker has since advanced.
  - `world.claim(): Promise<void>` claims ownership at the world's current step, throwing `FenceError` if refused — and `StaleSnapshotError` if the adapter's latest persisted step is **ahead** of this world's. That staleness check is not redundant with the fence: a monotonic fence refuses a step at or below one already claimed, but a worker resuming an *older* snapshot claims a *lower* step, so if it claims first there is nothing to refuse it with. It would then be caught only at its first save — after its side effects had run, which is precisely the failure `claim()` exists to prevent, one boundary further out. `claim()` therefore guarantees a single winner both among workers resuming the **same** snapshot (the fence) and against workers resuming a **stale** one (the step check). **This is what makes side effects exactly-once, and the save-time fence alone does not**: fencing at save time stops the loser from persisting a divergent timeline, but by then its systems have already run — the refund is issued, the record is deleted. The resume recipe is therefore `load` → `await claim()` → `resume/run`. It requires a `fence`-capable adapter and throws otherwise, rather than implying an exclusivity it cannot provide.
  - `PersistenceAdapter.fence?(worldId, step)` claims the right to write a step, and must be **monotonic per worldId**: granting a step implicitly refuses that step and every step below it. Worlds created with `{ fence: true }` call it from `claim()` and again immediately **before each save** — the moment divergence would become durable, and already an awaited async boundary — and reject the run with `FenceError` when refused. Adapters must make the check-and-claim atomic against other writers (a conditional write, a compare-and-set, `O_EXCL`); a read followed by a separate write reintroduces the race it exists to close. `MemoryAdapter` and `@langecs/persist-fs` both implement it.
  Fencing is **opt-in per world and deliberately not implied by the adapter having the method**: a time-travel world (R38) legitimately rewrites steps it has already written, and an automatic fence would refuse its own replay.
- **R58** **Write cadence.** `createWorld({ saveEvery: 'barrier' | 'quiescence' | number })`, default `'barrier'` (every committed step — required for step-level time travel, R38). `'quiescence'` writes only at run end; a number writes every N steps. Run end always writes, at every setting, so a quiesced world is never left unpersisted — and because quiescence *is* the pause in this engine, `'quiescence'` still captures every boundary a human-in-the-loop flow resumes from. What it gives up is the intermediate steps, i.e. time travel. This matters because `snapshot()` serialises every entity's every component, so cost per step scales with total world size rather than with what changed.
